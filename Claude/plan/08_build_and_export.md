# 08 · Build, Render & Export Pipeline

## 1. Tech stack (static, no app logic: these are design mockups)
- **HTML + Tailwind CSS** (Tailwind standalone CLI or `npm i -D tailwindcss`), config extends colors from `tokens.css`.
- **Fonts:** Inter + JetBrains Mono from Google Fonts (`<link>`), Montserrat 800 for logo work only.
- **Icons:** Lucide as **inline SVG** (`lucide-static` npm package, copy the SVG markup). No icon fonts.
- **Charts:** **hand-built inline SVG** (generated by a small helper `src/lib/chart.js` that outputs `<svg>` paths from `mock.json` at build time). Do *not* use canvas charts: they rasterize in Figma and may blur.
- **Images:** only SVG illustrations + one camera image for Vision (≥ 2000 px wide source, or an SVG illustration of a bead).
- **Renderer:** Playwright (Chromium) for PNG + PDF.

## 3. Screen file conventions
- `<body data-frame="desktop">` → 1440×900, `data-frame="tablet"` → 1024×768. Content must fit exactly, no scrollbars.
- Each screen self-contained (links shared CSS), no JS required to render except optional static chart generation before screenshot.
- Header comment in every file: `<!-- S08 · Live Print Monitor · /prints/:jobId/live · US-03,04,06,07 -->`.

## 4. Render script (`scripts/render.mjs`)
```js
import { chromium } from 'playwright';
import fs from 'node:fs';
const frames = { desktop:{width:1440,height:900}, tablet:{width:1024,height:768} };
const browser = await chromium.launch();
for (const f of fs.readdirSync('src/screens').filter(f=>f.endsWith('.html'))) {
  const page = await browser.newPage({ deviceScaleFactor: 2 });
  await page.goto('file://' + process.cwd() + '/src/screens/' + f);
  const kind = await page.getAttribute('body','data-frame') || 'desktop';
  await page.setViewportSize(frames[kind]);
  await page.evaluate(() => document.fonts.ready);
  await page.screenshot({ path: `exports/${f.replace('.html','')}@2x.png` });
  await page.close();
}
// Report PDF (Letter, vector text)
const rp = await browser.newPage();
await rp.goto('file://' + process.cwd() + '/src/report/report.html');
await rp.evaluate(() => document.fonts.ready);
await rp.pdf({ path: 'exports/PRIME_Milestone2.pdf', format: 'Letter', printBackground: true, preferCSSPageSize: true });
await browser.close();
```
Repeat the same loop for `src/lofi`, `src/journey` (landscape: 1584×1224 @2×).

## 5. Report document (`report.html`)
- `@page { size: Letter; margin: 0.6in; }`, each page a `<section class="page">` with `break-after: page`. Journey map page uses a named page `@page landscape { size: Letter landscape; }`.
- Headings styled like Milestone 1 (blue numbered headings) but using `blue-600` / `navy-900` from the new palette.
- Screens placed as `<img src="../../exports/S07-dashboard@2x.png">` with explicit widths. **Effective resolution check:** 2880 px across 7.3 in ≈ 395 dpi ✔. Never upscale an image beyond its native width / 2.
- Tablet screens shown in a simple CSS device frame (rounded 24 px, 14 px dark bezel) for context.
- Page 9: Figma view link (and QR code SVG), contributions, use of AI (honest, same style as Milestone 1).

## 6. Figma (rubric: "Figma or Adobe XD")
1. Deploy `src/` temporarily (GitHub Pages or Netlify Drop) **or** serve locally.
2. In Figma, run **html.to.design** (by ‹div›RIOTS): import each screen URL at its frame size (1440 or 1024). This produces editable layers (text, auto-layout-ish frames, vector icons). Check the plugin's free-tier import limit before starting; if limited, import only the 16 Hi-Fi screens and place lo-fi/journey as PNG @2×.
3. Fallback: drag `*@2x.png` into 1440/1024 frames (still crisp, less editable).
4. Figma file structure: pages `00 Cover & Logo` · `01 Design System` (create **Color Styles** from the palette tokens + text styles, which reinforces page 2) · `02 Lo-Fi` · `03 Hi-Fi Desktop` · `04 Hi-Fi Tablet` · `05 Onboarding & Gamification` · `06 Journey Map`.
5. **Add prototype links** (Figma Prototype tab) along the routes from `02_…` §3: Login → MFA → Welcome → … → Dashboard → Live ↔ Vision/Trends/AI. This proves the routes are interactive; mention it on page 3 and include the prototype link on page 9.
